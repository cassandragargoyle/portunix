# specpm

Initialize project-management specifications (spec-kit-pm)

## Usage

```bash
portunix specpm [options] [arguments]
```

## Full Help

```
ptx-specpm is the Portunix helper for the spec-kit-pm framework. It is
registered with the dispatcher as 'portunix specpm' and bootstraps the
spec-kit-pm scaffold inside a working directory so AI agents can drive
project-management workflows (Charter, plan, risks, decisions, KPIs,
reports) via /specpm.* slash-commands or skills.

The kit content lives upstream at CassandraGargoyle/spec-kit-pm and is
fetched at runtime via shallow clone (default) or read from a local path
(forks / air-gapped). Subsequent runs of the same kit ref are served from
a per-ref cache and never hit the network.

This binary is typically invoked by the main portunix dispatcher and
should not be used directly.

Usage:
  ptx-specpm [command]

Available Commands:
  check       Show installed agents, wired integration, profile, and kit ref for the current project
  completion  Generate the autocompletion script for the specified shell
  help        Help about any command
  init        Bootstrap a project with the spec-kit-pm scaffold
  integration Inspect and manage AI-agent integrations
  upgrade     Refresh .specpm/ kit cache; never touches specs/project/
  version     Print helper version and bundled spec-kit-pm pinned ref

Flags:
  -h, --help      help for ptx-specpm
  -v, --version   version for ptx-specpm

Use "ptx-specpm [command] --help" for more information about a command.

```

### init

Bootstrap a project with the spec-kit-pm scaffold

```
init bootstraps the spec-kit-pm scaffold in a project directory.

Forms:
  ptx-specpm init <PROJECT_NAME>     Create new directory and scaffold inside it
  ptx-specpm init .                  Initialise in the current directory
  ptx-specpm init --here             Same as 'init .'

The scaffold has two roots (per ADR-040):
  .specpm/                Kit cache — regenerated by init / upgrade
  specs/project/<id>/     User artifacts — never overwritten by re-runs

Default --source is 'git': the kit is shallow-cloned from upstream at the
pinned ref into ~/.cache/portunix/specpm/<ref>/ on the first run; later
runs read from cache. For air-gapped operation use --source <path> against
a vendored fork.

Usage:
  ptx-specpm init [PROJECT_NAME|.] [flags]

Flags:
      --force                        Overwrite scaffold files (never user artifacts)
  -h, --help                         help for init
      --here                         Initialise in the current directory
      --ignore-agent-tools           Skip detection of installed agent CLIs
      --integration string           AI agent integration target (e.g. 'claude')
      --integration-options string   Driver-specific options (e.g. --integration-options="--skills")
      --profile string               Apply a profile bundled with the kit or installed under .specpm/profiles/
      --project-id string            Project ID under specs/project/<id>/ (default: derived from target dir name)
      --ref string                   Override pinned ref (with --source git); default = DefaultPinnedRef
      --source string                Kit source mode: 'git' (default) or absolute filesystem path (default "git")
```

### upgrade

Refresh .specpm/ kit cache; never touches specs/project/

```
upgrade refreshes the .specpm/ kit cache for the project in the current
directory. The project's currently-pinned ref (recorded in .specpm/kit.json) is
the source of truth; pin movement is always an explicit --ref or --to-default.

Forms:
  ptx-specpm upgrade                Refresh from project's pinned ref (idempotent on cache hit)
  ptx-specpm upgrade --ref <X>      Bump project pin to <X>; fetch and refresh
  ptx-specpm upgrade --to-default   Shortcut for --ref <DefaultPinnedRef>
  ptx-specpm upgrade --source <p>   Switch to local-path provider; refresh from <p>

Carve-outs preserved on every upgrade (per ADR-041 D3):
  .specpm/kit.json        manifest (rewritten in place)
  .specpm/extensions/     user-installed extensions (Phase 3+)
  .specpm/presets/        user-installed presets (Phase 3+)

Files under specs/project/<id>/ are NEVER touched.

Usage:
  ptx-specpm upgrade [flags]

Flags:
  -h, --help            help for upgrade
      --ref string      Bump project pin to this git ref (tag or commit SHA)
      --source string   Switch to local-path provider (absolute path); incompatible with --ref
      --to-default      Shortcut for --ref <DefaultPinnedRef> (track this Portunix release)
```
