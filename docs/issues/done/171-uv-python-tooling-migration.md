# Issue #171: Migrate Python Tooling to uv

- **Type**: Enhancement / Refactoring
- **Priority**: Medium
- **Status**: ✅ Implemented
- **Labels**: enhancement, tooling, python, uv, developer-experience, ci-cd
- **Created**: 2026-04-17
- **ADR**: [ADR-039](../../adr/039-uv-python-tooling-adoption.md)

## Description

Replace the current `pip` + `venv` + `requirements.txt` workflow used for
project scripts and integration test dependencies with [uv](https://docs.astral.sh/uv/).
The Go codebase, plugin SDKs, and `ptx-python` helper are **not** in scope.

Motivation, alternatives analysis, and decision rationale are documented in
**ADR-039**. This issue tracks the concrete implementation.

## Scope

In scope:

- Root-level Python manifest (`pyproject.toml`, `.python-version`, `uv.lock`)
- `scripts/setup-venv.{sh,ps1,cmd}` — provisioning via `uv sync`
- `scripts/activate-venv.{sh,ps1,cmd}` — removed (superseded by `uv run`)
- `scripts/*.py` — PEP 723 inline metadata headers
- CI/CD policy — verify no current pip usage; add uv as the standard for any
  future Python job
- Documentation — `README.md`, `test/README.md`,
  `docs/contributing/TESTING-PYTHON.md`,
  `docs/contributing/CODE-STYLE-PYTHON.md`, `CLAUDE.md`
- **`portunix install uv` package** — add `uv.json` to
  `src/helpers/ptx-installer/assets/packages/` so contributors can install uv
  through the standard Portunix package flow (scope added during
  implementation; ADR-039 mentions this as a follow-up, but it is small enough
  to bundle with the migration)

Out of scope:

- `ptx-python` helper (covered by ADR-033 and its issues)
- Python plugin SDK (`src/helpers/ptx-trace/sdk/python/`)
- Packaging Portunix as a Python distribution

## Implementation Plan

1. **Bootstrap manifest**
   - `uv init --bare` (or hand-write `pyproject.toml`)
   - Add the `test` dependency group with the 8 existing deps
   - Generate `uv.lock` via `uv lock`
   - Commit `pyproject.toml`, `.python-version`, `uv.lock`
2. **Rewrite setup scripts**
   - Port `setup-venv.sh` → `uv sync [--group test]`
   - Mirror for PowerShell + CMD
   - Manual smoke test on Linux + Windows (or Windows container)
3. **Annotate standalone scripts** with PEP 723 headers
4. **Delete legacy requirements files**
5. **Update documentation** (README, test/README, TESTING-PYTHON,
   CODE-STYLE-PYTHON, CLAUDE.md)
6. **Container verification** per TESTING_METHODOLOGY.md
7. **PR with ADR reference** + tester acceptance per
   ISSUE-DEVELOPMENT-METHODOLOGY.md

## Risks & Mitigations

| Risk | Mitigation |
| ---- | ---------- |
| Contributors without `uv` installed are blocked | Setup scripts detect missing `uv` and print install instructions; follow-up issue adds `uv` to ptx-installer |
| Windows CMD/PowerShell uv invocation differs from bash | Verify all three setup scripts in container or VM before acceptance |
| `uv.lock` merge conflicts | Same treatment as `go.sum` — regenerate with `uv lock` and commit |
| External tooling expects `requirements.txt` | Documented workaround: `uv export --format requirements-txt > requirements.txt` on demand; not committed |

## Rollback Plan

1. `git revert` the migration commit(s)
2. Restored `requirements.txt` and `test/requirements-test.txt` work
   immediately with existing `setup-venv` scripts (since `.venv/` layout never
   changed)
3. No database, no release artifact, no user data is affected
