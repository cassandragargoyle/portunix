# ptx-specpm — `portunix specpm`

Initialize project-management specifications using the
[`spec-kit-pm`](https://github.com/CassandraGargoyle/spec-kit-pm) framework.
Phase 1 of [Issue #183](../issues/internal/183-ptx-specpm-helper-implementation.md);
Phase 2 of [Issue #184](../issues/internal/184-ptx-specpm-phase2-upgrade.md);
architecture locked in
[ADR-040](../adr/040-ptx-specpm-helper-architecture.md) and
[ADR-041](../adr/041-ptx-specpm-phase2-upgrade-and-airgapped.md).

## What it does

`portunix specpm init` writes a two-part scaffold into your project so an AI
agent (Claude Code by default) can drive Charter, plan (Mermaid Gantt),
risks, decisions, KPIs, and stakeholder reports through `/specpm.*`
slash-commands or skills.

The kit (templates, agent prompts, workflows, profiles) lives upstream at
`CassandraGargoyle/spec-kit-pm`. The helper contains only Go logic; kit
content is fetched at runtime via shallow clone of a pinned ref into
`~/.cache/portunix/specpm/<ref>/` (per-ref, immutable, never expires).
Subsequent `init`s of the same ref are served from cache and never hit the
network.

## Quick start

```bash
# Bootstrap a new project
portunix specpm init my-project --integration claude

# Initialise inside an existing repo
portunix specpm init . --integration claude
portunix specpm init --here --integration claude

# Air-gapped: vendor the kit from a fork or local mirror (see "Air-gapped workflow" below)
portunix specpm init my-project --integration claude --source /path/to/spec-kit-pm

# Refresh the kit cache (Phase 2)
portunix specpm upgrade                              # follow the project's pinned ref
portunix specpm upgrade --to-default                 # track this Portunix release
portunix specpm upgrade --source /path/to/spec-kit-pm  # air-gapped refresh

# Skills mode (Claude Code)
portunix specpm init my-project --integration claude --integration-options="--skills"

# Inspect detected agents and pinned kit ref
portunix specpm check
portunix specpm version
portunix specpm integration list
```

## Project layout (ADR-040 D1)

```text
.specpm/                          # Kit cache — regenerated by init / upgrade
├── memory/governance.md          # Long-lived PM context
├── templates/                    # From upstream templates/
├── agents/                       # From upstream agents/
├── workflows/                    # From upstream workflows/
├── profiles/                     # Bundled profiles (e.g. example-company)
└── kit.json                      # Manifest (source, ref, profile, integration)

specs/                            # User artifacts — NEVER overwritten
└── project/<project-id>/
    ├── project.md                # Charter (REQUIRED — PM-agent preflight reads this)
    ├── gantt.md                  # AI Plan output (Mermaid)
    ├── risks.md
    ├── kpis.md
    ├── decisions.md
    ├── execution/
    └── validation/

.claude/commands/specpm.*.md      # Slash-command bundle (default mode)
.claude/skills/specpm-*/SKILL.md  # Skills bundle (--integration-options="--skills")
CLAUDE.md                         # Augmented with @.specpm/memory/governance.md
~/.cache/portunix/specpm/<ref>/   # Per-ref runtime cache (immutable)
```

The split between `.specpm/` (kit) and `specs/project/<id>/` (artifacts)
follows the upstream contract: the PM-agent preflight requires
`specs/project/<project-id>/project.md` with `status: active`. User content
under `specs/project/` is never touched by `init` or `--force`.

## Flags

| Flag | Purpose |
| ---- | ------- |
| `--here` | Initialise in current directory (equivalent to `init .`) |
| `--force` | Overwrite scaffold files (kit cache only); user artifacts stay sacred |
| `--integration <agent>` | Phase 1: `claude` only |
| `--integration-options="--skills"` | Emit Claude Code skills instead of slash-commands |
| `--profile <name>` | Apply a profile from `~/.config/portunix/specpm/profiles/<name>/` or `.specpm/profiles/<name>/` |
| `--source git\|<path>` | Kit source mode; default `git` |
| `--ref <tag-or-sha>` | Override pinned ref when `--source git`; default = `kit.DefaultPinnedRef` |
| `--ignore-agent-tools` | Skip detection of installed agent CLIs |
| `--project-id <id>` | Override the derived project id under `specs/project/<id>/` |

## Requirements

- **Default `--source git`**: a `git` binary on `PATH` and network access on
  the **first run** for a given ref. Subsequent runs of the same ref are
  cache-served.
- **Air-gapped first run**: use `--source <absolute-path>` against a local
  checkout or fork of `spec-kit-pm` (see "Air-gapped workflow" below).

## `upgrade` (Phase 2)

`upgrade` refreshes `.specpm/` from the project's currently-pinned ref.
**`specs/project/<id>/` is never touched.** Pin movement is always explicit
(`--ref` or `--to-default`); plain `upgrade` is a refresh-only verb.

| Form | Behaviour |
| ---- | --------- |
| `portunix specpm upgrade` | Refresh `.specpm/` from the project's pinned ref (read from `.specpm/kit.json`). Idempotent on cache hit + unchanged content (only `written_at` moves). |
| `portunix specpm upgrade --ref <X>` | Bump project pin to git ref `<X>` (tag or commit SHA), fetch, refresh. Implies `--source git`. |
| `portunix specpm upgrade --to-default` | Shortcut for `--ref <DefaultPinnedRef>` — track this Portunix release. |
| `portunix specpm upgrade --source <path>` | Switch project to local-path provider (air-gapped refresh). `kit.json.source = <path>`, `ref = "(local path)"`. Subsequent plain `upgrade`s reuse this source. |

### `.specpm/` overwrite policy (ADR-041 D3)

`upgrade` authoritatively refreshes the kit cache. Files added or removed
upstream are mirrored exactly. Three carve-outs survive every `upgrade`:

| Path | Reason |
| ---- | ------ |
| `.specpm/kit.json` | Manifest — rewritten in place with new `source`/`ref`/`written_at` |
| `.specpm/extensions/` | User-installed extensions (Phase 3+) |
| `.specpm/presets/` | User-installed presets (Phase 3+) |

Everything else under `.specpm/` (`templates/`, `agents/`, `workflows/`,
`profiles/<bundled>/`, `memory/`, `scripts/`) is **wholly refreshed** —
hand-edits to those paths are by-design lost. Customisation belongs in
**profiles** (user > org > bundled precedence) or in **extensions** /
**presets**, never in ad-hoc edits to the kit cache.

### Drift between project pin and Portunix release

When a project is pinned to a ref older or newer than the Portunix release's
`DefaultPinnedRef`, `portunix specpm check` adds an informational drift line:

```text
Drift            : binary recommends <DefaultPinnedRef> (this Portunix release)
                   Run 'portunix specpm upgrade --to-default' to follow the recommendation.
```

The drift line is informational only — exit code is unchanged, and `upgrade`
without flags **does not** auto-bump.

## Air-gapped workflow

The supported air-gapped pattern is **mirror once on a connected host,
init/upgrade many on the disconnected host**.

### 1. Mirror upstream once (connected host)

```bash
git clone --depth 1 --branch <ref> https://github.com/CassandraGargoyle/spec-kit-pm.git ./mirror
tar czf spec-kit-pm-<ref>.tar.gz mirror/
# Transfer spec-kit-pm-<ref>.tar.gz to the air-gapped host.
```

### 2. Extract on the air-gapped host

```bash
tar xzf spec-kit-pm-<ref>.tar.gz -C /opt/
# Stable location: /opt/spec-kit-pm/
```

### 3. Use the mirror for `init` and `upgrade`

```bash
# First-time bootstrap inside an air-gapped project
portunix specpm init . --integration claude --source /opt/spec-kit-pm

# Later, after replacing the mirror with a newer ref
portunix specpm upgrade --source /opt/spec-kit-pm
```

When the mirror is updated (re-extract a new tarball over the same path), a
plain `portunix specpm upgrade` re-reads from the recorded `--source <path>`
and refreshes `.specpm/`. **No network is contacted, no `git` binary is
required.**

### Offline error hint

If `--source git` is used and either the local `git` binary is missing or
the cache misses for the requested ref while the network is unreachable, the
helper exits non-zero with a remediation hint pointing at this section.

## What's not in this scope

- Extensions and presets (Phase 3 — separate issue/ADR)
- Drivers other than Claude Code: Copilot, Cursor, Gemini CLI, Codex CLI
  arrive in Phase 4
- Native non-AI workflow subcommands (`spec`, `plan`, ...) are deferred /
  spin-off (Phase 5)
- MCP surface — follow-up `ptx-mcp` collaboration
